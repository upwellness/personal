01 · Executive scope

ผลิตภัณฑ์ที่ตั้งใจสร้าง — และสิ่งที่ไม่อ้าง

ตามต่อช่วยทีม SME ไทย 1–10 คนเก็บบริบทหลังคุยลูกค้า ตั้ง next action และวันครบกำหนด แล้วเริ่มงานจากคิว Today/Overdue โดยยังใช้ LINE, email และโทรศัพท์ในเครื่องมือเดิม

คำสัญญาที่ตรวจสอบได้

  • Contacts + timeline + owner
  • Quick capture และ next action ใน flow เดียว
  • Overdue, Today, Upcoming, No next action
  • CSV import/export และ concierge setup 30–45 นาที

ขอบเขตเชิงความจริง

  • “บันทึกแล้ว” = บันทึกในตามต่อ ไม่ใช่ส่งแล้ว
  • Copy/deep link ≠ sent, delivered หรือ read
  • Action completed ≠ ลูกค้าตอบหรือเกิดรายได้
  • ไม่มี push/email/LINE reminder อัตโนมัติ

เป้าหมาย pilot

G-01 / Activation

สร้าง/import ≥1 contact และเห็น ≥1 open action ใน setup session

G-02 / Friction

เป้าทดสอบ median quick-capture ≤60 วินาที (ยังไม่ใช่ผลที่วัดได้แล้ว)

G-03 / Explicit state

ปลาย pilot: action coverage ≥70% ตามนิยาม canonical

G-04 / Habit

workspace active ≥3 distinct local days/week ภายใน 21 วัน

G-05 / Commercial

นับ WTP เฉพาะเงิน/มัดจำรับจริงและ renewal จริง

G-06 / Isolation

cross-workspace incident = 0 และ negative tests ครบ

02 · Users & jobs

ใครใช้ ใครซื้อ และงานที่ต้องสำเร็จ

Primary ICP Hypothesis

owner-led B2B service teams / SME ไทย 1–10 คน (นiche แรก 1–5 คน) ที่ขายผ่าน LINE + email + โทร, ข้อมูลกระจายในชีต/สมุด/contacts, มีเหตุลืมหรือตามช้า ≥2 ครั้งใน 30 วัน และยอมเริ่มแบบ manual + CSV.

ไม่ใช่ pilot แรก

ทีมที่ต้องมี enterprise approval, call center, omnichannel inbox, marketing automation, API/integration หรือ CRM pipeline ซับซ้อนก่อนเริ่ม; ธุรกิจที่ต้องใส่ข้อมูลอ่อนไหว.

Owner / Buyer

สร้าง workspace, กำกับข้อมูล, export/deletion, ซื้อ pilot และตัดสิน renewal.

Admin

import/export, members (ยกเว้น owner), tags/templates, workspace operations.

Member

capture, contact/timeline, complete/reschedule, assign ภายใน workspace.

03 · Core workflows

เส้นทางใช้งานหลัก

J-01 · Concierge onboarding + CSV import
  1. Owner สร้าง workspace, เลือก IANA timezone และยอมรับ Terms/Privacy เวอร์ชันจริง
  2. เชิญสมาชิกตาม entitlement; อธิบาย data minimization และ CSV template
  3. Upload → map → preview/validate/dedupe; preview ห้ามเขียน production table
  4. แสดง total/valid/error/duplicate/skipped แล้วให้ยืนยัน partial valid-row import
  5. Commit แบบ idempotent; ดาวน์โหลด row-level error report; raw file purge ตาม config
  6. ตั้ง tags/templates 3–5 ค่า แล้วจัดการ contacts ใน No next action

สำเร็จเมื่อ: ไม่มี silent row loss, trace ได้ด้วย batch ID และ owner เห็นคิวแรก.

J-02 · Quick capture หลังโทร/แชท
  1. เปิด Capture จาก bottom nav/FAB; ค้นหา contact หรือสร้างด้วยชื่ออย่างเดียว
  2. เลือก channel, direction, outcome; note optional พร้อมคำเตือนไม่ใส่ข้อมูลอ่อนไหว
  3. เลือก disposition: create action / no action yet / close contact
  4. ส่ง UUID idempotency key; server transaction สร้าง contact (ถ้ามี) + interaction + disposition + audit
  5. รอ server confirm แล้วแสดง “บันทึกในตามต่อแล้ว” — ห้าม optimistic claim
J-03 · ทำงานจาก Today / Overdue
  1. เปิดคิว “ของฉัน”; Overdue แสดงก่อน Today จาก server time/workspace timezone
  2. โทร, copy template หรือเปิด allowlisted deep link โดย app ไม่เปลี่ยน state เป็น sent
  3. กลับมา complete พร้อม optional outcome และ optional next action แบบ atomic
  4. หรือ reschedule/cancel/close; server confirm แล้วจึงออกจาก open queue
J-04 · Handoff และ J-05 · Export/exit

Handoff: เปิด timeline → reassign contact/action ให้ active member ใน tenant เดียวกัน → assignee เห็นใน “ของฉัน” → audit actor/time/changed fields.

Exit: owner/admin ขอ workspace-scoped export → ได้ snapshot/เวลา generate → owner ขอ deletion ด้วย re-auth/impact preview/cooling policy ที่อนุมัติแล้ว.

Cross-cutting NFR

NFR-01 · UX/A11y

360px ไม่มี horizontal scroll, touch target ~44px, keyboard/focus, WCAG 2.1 AA target, status ไม่ใช้สีอย่างเดียว.

NFR-02 · Performance

เป้าทดสอบ list usable ≤2.5s p75; write confirm ≤2s p75; pagination 25–50. ยังไม่ใช่ measured performance.

NFR-03 · Security

TLS, session cookie controls, origin/CSRF, rate limits, CSP, no service role in browser, PII-redacted logs.

NFR-04 · Reliability

request ID, structured logs, migration plan, no optimistic success, backup/export recovery drill.

NFR-05 · Localization

Thai default, UTF-8, UTC persistence, IANA workspace TZ, ISO 8601 API, avoid Buddhist/Gregorian ambiguity.

Error contract

401 auth, 403/404 authorization/privacy, 409 conflict, 422 validation, 429 limit, generic 5xx; Thai retryable copy + request ID.

Supabase entities: implemented baseline vs target contract

ต้องแยก “สิ่งที่มีใน supabase/schema.sql” ออกจาก logical target ใน PRD/SPEC เพื่อไม่สร้างภาพว่าทุก requirement ถูก implement แล้ว.

profilesมีจริง: user-owned display metadata
workspacesมีจริง: name, creator; target เพิ่ม slug/timezone/locale/status/demo/retention
workspace_membersมีจริง: owner|member; target ต้อง reconcile admin/status/invites
contactsมีจริง: channels, text[] tags, active|closed; target เพิ่ม archive, normalized IDs, close metadata, version
interactionsมีจริง: kind/note/time; target เพิ่ม direction/outcome/soft delete/idempotency/audit
follow_upsมีจริง: due/assignee/open|completed|cancelled; target เพิ่ม cancel metadata/version/idempotency
tags / contact_tags / templateslogical target; ยังไม่อยู่ baseline schema (ปัจจุบัน tags เป็น array)
imports / row resultslogical target สำหรับ preview/commit/reconcile/purge; ยังไม่อยู่ baseline schema
idempotency / audit / privacy / policyrequired logical operations entities; ยังไม่อยู่ baseline schema
Schema reconciliation gate: baseline schema ใช้ role owner|member, contact active|closed, note บังคับมีค่า และ unique email ต่อ workspace ขณะที่ frozen SPEC ต้องมี admin, archived state, optional note, duplicate override, normalized tags และ operations/audit entities. ต้องออก migration/ADR ที่ reconcile ก่อน claim ว่า Must scope พร้อม.

Current RLS baseline

  • RLS enabled บน public tables; anon ไม่มี application-table privileges.
  • is_workspace_member / is_workspace_owner เป็น narrow SECURITY DEFINER, fixed search path, boolean only.
  • create_workspace สร้าง workspace + owner แบบ atomic; direct workspace insert ไม่ grant.
  • Cross-workspace triggers ตรวจ contact↔interaction/follow-up และ owner/assignee membership.
  • Owner-only workspace/membership mutation; tenant rows membership-scoped.
  • quick_capture RPC มี transaction แต่ baseline ยังไม่มี idempotency key/disposition/optional note contract เต็ม.

RLS / authorization invariant ที่ target ต้องผ่าน

ทุก tenant-owned row

workspace_id NOT NULL; SELECT/INSERT/UPDATE/DELETE ตรวจ active membership และ capability; child-parent workspace consistency บังคับใน DB.

Privileged operations

Import commit, export, deletion, member removal ตรวจ role ใหม่ทุก request ผ่าน server/RPC; query/body workspace ID ไม่เคยเพียงพอ.

Negative test actors

anonymous, removed member, member, admin, owner, cross-tenant guessed UUID และ accidental service-role exposure.

Proof standard

ทดสอบด้วย real JWT/PostgREST และ SQL role simulationอย่างน้อยสอง tenants; BFF-only test ไม่พิสูจน์ RLS.

Release sequence

  1. สร้าง migration history จาก schema source; run local reset/migration tests ใน disposable project
  2. ปิด schema gaps และ architecture decisions โดยบันทึก owner/date/ADR
  3. ตั้ง Preview project/callback/env แยก production; scan env/build artifacts ว่าไม่มี service key
  4. ทดสอบ RLS ด้วยผู้ใช้จริง 2 ราย/2 tenants ผ่าน PostgREST + direct SQL simulation
  5. รัน typecheck, lint, unit/integration, production build, security/privacy/CSV/timezone tests
  6. apply production migration ใน change window; ห้าม seed demo ใน customer production
  7. deploy แล้ว smoke login/logout/session/workspace/CRUD/capture/queue/import/export/mobile/config failure
  8. ผ่าน backup/export recovery, privacy/legal, quota/usage checks จึงรับ paid pilot data
07 · Privacy & security

Baseline ก่อนข้อมูลบุคคลจริง

ข้อกำหนดนี้เป็น product/security baseline ไม่ใช่คำปรึกษากฎหมาย. ต้องให้ privacy/legal reviewer ยืนยัน deployment, lawful basis, DPA, retention, subprocessor/transfer และ SLA จริง.

Purpose & roles

โดยทั่วไป pilot business เป็น controller ของ contact data และตามต่อเป็น processor ตามข้อตกลง — ต้องยืนยันตาม deployment. ใช้ข้อมูลเพื่อ follow-up ตามคำสั่ง workspace; ไม่ขายและไม่ใช้ train model.

Data minimization

ชื่อ required; phone/email/LINE/note optional; ไม่ขอ sensitive data. ไม่เก็บ full chat history. Import ไม่เท่ากับ marketing consent.

Access & telemetry

RLS + server auth, least privilege, no client service key. ห้าม log/analytics ชื่อ contact, note, phone, email, LINE ID, template body, CSV row, JWT/cookie หรือ raw DB error.

Rights & lifecycle

Verified access/correction/export/deletion/objection workflow; owner verification, ticket/audit/SLA; soft recovery แล้ว purge ตาม policy; backup behavior ต้องตรง notice.

08 · Test & release checklist

หลักฐานที่ต้องมี ไม่ใช่ช่องที่ติ๊กล่วงหน้า

ผล pass ต้องมาจากการรันจริงและ map Must stories → AC IDs. เอกสารนี้ไม่สร้างผลทดสอบสมมติ.

Authorization / isolation

  • Cross-tenant CRUD negative tests ทุก tenant table
  • anonymous/removed/member/admin/owner matrix
  • last-owner, inactive assignee, guessed UUID
  • export/privacy endpoint tenant isolation

Transactions / concurrency

  • Quick capture rollback/idempotency/double tap
  • Complete + optional outcome/next action atomicity
  • 409 optimistic conflict; preserve/reapply form
  • response lost after commit reconciliation

Time / lifecycle

  • Today/Overdue exact-now, midnight, browser/TZ mismatch
  • workspace timezone change impact
  • archive/close/reopen and action cancellation
  • counts/list predicates and pagination order

CSV / portability

  • UTF-8/BOM Thai round-trip
  • malformed quote/encoding/oversize/duplicate header
  • duplicate policy, partial crash, batch retry
  • formula injection and expiring download

Web / privacy / demo

  • XSS, malicious scheme, upload filename, CSRF
  • logout/cache/service worker leakage
  • telemetry PII schema + demo/operator exclusion
  • demo isolation, banner, sandbox, reset

Quality / operations

  • 360px, keyboard, screen-reader smoke, focus/contrast
  • typecheck/lint/unit/integration/build
  • bundle/source map secret scan
  • backup/export restore drill + migration rollback/forward plan

Release blockers

  • Must AC ใดไม่ผ่าน หรือไม่มี evidence
  • RLS/authorization negative tests ไม่ครบหรือพบ cross-workspace access
  • schema baseline ยังไม่ reconcile กับ frozen SPEC ที่จะขาย
  • privacy notice/Terms/DPA/retention/backup behavior ยังไม่อนุมัติ
  • demo isolation/claims ไม่ผ่าน หรือ analytics มี PII
  • มี Sev-1/Sev-2 open defect หรือ config fail-open

Definition of Done ต่อ feature

AC ผ่านด้วย automated test หรือ documented manual evidence; RLS/analytics review; loading/empty/error/offline/concurrent states; Thai truthfulness copy; telemetry ไม่มี PII; 360px + keyboard; migration/rollback; schema/API/docs updated.

Canonical metrics

  • Action coverage: contacts ที่ (active และมี ≥1 open action) หรือ closed ÷ contacts active+closed; archived exclude; รายงาน numerator/denominator + query version.
  • Active day: server-confirmed human event (interaction_created, action_completed, action_rescheduled) ใน distinct workspace local day; demo/operator/test exclude.
