UP Line

แพลตฟอร์ม LINE Bot อเนกประสงค์ multi-tenant — 12 โมดูล เลือกซื้อแยกได้ (à la carte) หรือเป็น tier ครอบคลุมผู้ช่วยส่วนตัว, broadcast, 🔥 ตรวจสลิปอัตโนมัติ, ขายของในแชท, จองคิว, FAQ AI, CRM และงาน HR ภายในองค์กร

01 ภาพรวมและเป้าหมาย

UP Line คืออะไร: แพลตฟอร์มเดียวที่ deploy บอท LINE ได้หลายตัว ประกอบจาก 12 โมดูล ที่เปิด/ปิดและซื้อแยกได้ผ่าน Admin Dashboard — ตั้งแต่ผู้ช่วยส่วนตัว, broadcast, ตรวจสลิปอัตโนมัติ (validated แล้วว่าเป็น hook หลัก), ขายของในแชท, จองคิว, FAQ AI, ไปจนถึงงาน HR

งานวิจัยที่นำมาสู่เอกสารนี้: multi-agent research 8 โดเมนคู่ขนาน → 88 ฟีเจอร์ดิบ → BA สังเคราะห์ 12 โมดูล → ทดสอบกับ 5 persona ลูกค้าจริงจาก Agent Persona DB → ปรับตามฟีดแบ็ก (ดู §15)

G1
1-1 + Group chat แยกบริบทถูก
G2
Assistant: todo+calendar+news
G3
Broadcast custom message
G4
Admin Dashboard (BFF)
G5
Multi-tenant, modular, API-key optional
G6 🔥
Slip Verification = ตัวปิดการขายหลัก
G7
ราคา Tier + À la carte

ตัวชี้วัดความสำเร็จ (KPI)

  • ตั้งบอทลูกค้าใหม่ครบภายใน < 30 นาที ผ่าน Guided Onboarding
  • Webhook ตอบกลับ p95 < 2 วินาที · Scheduled push ตรงเวลา ±1 นาที
  • Slip Verification แม่นยำ ≥ 99%
  • ลูกค้าเปิด/ปิดโมดูล+เห็นราคาเปลี่ยน real-time เอง 100% ผ่าน Dashboard

03 ขอบเขต

✅ In Scope (v1 build)

  • Core Bot Engine + Admin Dashboard (Module Catalog)
  • Assistant + Broadcast (Starter bundle)
  • Slip Verification — priority สูงสุด build ลำดับ 2
  • โมดูลที่เหลือ — ออกแบบสถาปัตยกรรมไว้ ทยอย build

🚫 Non-Goals (v1)

  • Rich menu editor drag-drop เต็มรูปแบบ
  • แพลตฟอร์มอื่นนอก LINE
  • เชื่อม Shopee/Lazada Seller Center, IG DM — เฉพาะ 1 persona ไม่ recur
  • SOC2/pentest certification เต็มรูปแบบ — operational commitment ไม่ใช่ product feature

🔥 6.5 Slip Verification & Payment OCR — priority สูงสุด

Validated: 4/5 persona เลือกเป็นอันดับ 1 — "เจ็บจริงเพราะเงินหายจริง"

อ่าน QR สลิป → เช็ค API ธนาคาร (SlipOK/EasySlip) → กันสลิปปลอม/ซ้ำ → auto-reconcile กับออเดอร์ → เฝ้ากลุ่มขายของ → สรุปยอด → แจ้งเตือน fraud

API: SlipOK/EasySlip ~1-3 บาท/สลิป · 500-2,000 สลิป/เดือน = ~500-6,000 บาท/เดือน

  • Free Trial 14 วัน ทุก tier

  • ราคา external API เป็นตัวเลขจริง ไม่ใช่แค่ "แยกจ่าย"
  • Guided Onboarding ช่วย setup จริงในเดือนแรก

▸ กลุ่มตารางและความสัมพันธ์หลัก (ไม่วุ่นวาย — เห็นเฉพาะเส้นที่สำคัญ)

upl_tenants · upl_users_admin · upl_module_catalog · upl_module_subscriptions
↓ tenant เป็นเจ้าของ
B · BOTS & TARGETS
upl_bots · upl_targets · upl_module_configs
↓ target สร้างข้อมูลการใช้งาน
C · CORE OPS
upl_message_logs · upl_todos · upl_scheduled_jobs · upl_calendar_links · upl_broadcasts
D · MODULE DATA
upl_slip_verifications · upl_bookings · upl_orders · upl_leads
E · SECURITY
upl_provider_credentials (ผูกกับ A โดยตรง)

13 ความปลอดภัย + Multi-tenant

  • Tenant isolation: RLS ทุกตาราง; BFF เป็นชั้นเดียวที่ mint claim
  • Module entitlement check: ทุก request ต้องเช็ค MODULE_SUBSCRIPTIONS.enabled ก่อนทำงาน
  • Secrets: token/API key ภายนอกเข้ารหัส ไม่ส่งกลับ frontend
  • Slip/PII: เก็บ slip_ref_hash แทนภาพดิบ; e-KYC เก็บตาม PDPA data residency
  • Webhook: verify signature ทุกครั้ง + dedupe
  • Data Export & Portability: dump ข้อมูลได้ทุกเมื่อ (กัน vendor lock-in)
  • Audit retention: ขั้นต่ำ 1 ปี configurable
